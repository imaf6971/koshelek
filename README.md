# Кошелёк

Нативное iOS-приложение для личных финансов: SwiftUI + SwiftData + Swift Charts, iOS 17+, интерфейс целиком на русском.
Данные хранятся только на устройстве: нет аккаунтов, бэкенда и сетевых запросов.

## Быстрый старт

Нужны Xcode 16+ и [XcodeGen](https://github.com/yonaskolb/XcodeGen).

```bash
brew install xcodegen
xcodegen generate                      # создаёт Koshelek.xcodeproj из project.yml
open Koshelek.xcodeproj                # или собирайте из командной строки (ниже)
```

Список доступных симуляторов: `xcrun simctl list devices available` (подставьте любое имя вместо `<имя симулятора>`; на iOS 27.1 доступен, например, «iPhone Duo»).

Сборка и тесты на симуляторе:

```bash
xcodebuild -project Koshelek.xcodeproj -scheme Koshelek \
  -destination 'platform=iOS Simulator,name=<имя симулятора>' -derivedDataPath build build

xcodebuild -project Koshelek.xcodeproj -scheme Koshelek \
  -destination 'platform=iOS Simulator,name=<имя симулятора>' -derivedDataPath build test
```

Запуск на симуляторе:

```bash
xcrun simctl boot "<имя симулятора>"      # если ещё не запущен
xcrun simctl install booted build/Build/Products/Debug-iphonesimulator/Koshelek.app
xcrun simctl launch booted com.imaf6971.koshelek
```

Демо-данные (только DEBUG): кнопка на экране первого запуска, «Настройки → Разработка», либо аргумент запуска
`-seedDemo` (`xcrun simctl launch booted com.imaf6971.koshelek -seedDemo`). Там же есть «Очистить все данные».

`Koshelek.xcodeproj` не хранится в репозитории, он всегда генерируется из `project.yml`.

## Локализация

Все строки интерфейса лежат в `Koshelek/Resources/Localizable.xcstrings`. Ключ — русский текст.
Файл собирается скриптом из исходников; после добавления или изменения строк запустите:

```bash
python3 scripts/gen_strings.py
```

Правила: в коде используйте `Text("Русский текст")` или `L("…")`; для подстановок — `LF("Всего: %@", value)`
(интерполяция `\(…)` в локализуемых литералах запрещена, скрипт сообщит об ошибке).
Чтобы добавить язык, добавьте его локализацию в каталог строк в Xcode.

## Архитектура

```
Koshelek/
  App/            точка входа, корневой экран, вкладки, FAB, роутер листа ввода
  DesignSystem/   Theme (цвета light/dark, шрифты, отступы, радиусы, палитра), общие компоненты
  Domain/         чистый Swift без SwiftUI/SwiftData: деньги, периоды, баланс, аналитика,
                  бюджеты, прогноз, генерация повторов, фильтры
  Data/           модели SwiftData, настройки, сервисы (повторяющиеся операции, уведомления,
                  резервная копия, xlsx), демо-данные (DEBUG), точка расширения ImportSource
  Features/       экраны SwiftUI по разделам, ViewModel'и там, где есть заметное состояние
KoshelekTests/    unit-тесты Domain и Data
```

- **Domain отделён от хранилища.** Логика работает с value-типами `TxRecord` и `CategoryInfo`, а `@Model`-объекты
  превращаются в них через `Transaction.record` и `Category.info`. Поэтому тесты не требуют `ModelContext`.
- **Деньги** везде `Decimal`; суммы в JSON-копии хранятся строками, чтобы не терять точность.
- **Переводы** — одна операция с `toAccount`. `BalanceCalculator` двигает деньги между счетами,
  а `AnalyticsEngine` их игнорирует, поэтому в доходах и расходах переводов нет.
- **Повторяющиеся операции:** `RecurrenceGenerator` считает даты, `RecurringService` создаёт недостающие при запуске
  и выходе на передний план. Дубликатов нет: учитываются `lastGeneratedDate` и пары (правило, дата).
  Удалённая вручную сгенерированная операция не восстанавливается.
- **Прогноз:** `баланс − средний расход в день × оставшиеся дни ± плановые платежи до конца месяца`.
- **Экспорт xlsx:** собственный писатель Office Open XML (`XLSXWriter`) с минимальным ZIP-контейнером
  без сжатия. Есть строка заголовка, формат дат `dd.mm.yyyy`, формат сумм `#,##0.00`, закреплённая шапка и автофильтр.
  Расходы пишутся со знаком минус.
- **Резервная копия:** `BackupService` сначала валидирует файл (формат, версия, ссылки между сущностями),
  и только после подтверждения пользователя заменяет данные.
- **Импорт CSV позже:** протокол `ImportSource` возвращает `ImportedTransaction`. Новый импортёр
  добавляется отдельным типом, а модели и экспорт менять не придётся.

## Надёжность данных и правила разработки

- **Удаление и SwiftUI.** SwiftData падает, если экран читает поле объекта, который только что удалили. Поэтому: списки строятся
  из значений (`TxRowData`, `BudgetRowData` и локальные структуры строк), а не из моделей; листы и переходы хранят только
  идентификатор (`ItemID`, `EntryRequest.transactionID`), модель ищется заново при каждой отрисовке; все `@Query` читаются через `.live`.
  Не передавайте `@Model` в строки списка и не читайте его поля в замыканиях `ForEach`.
- **Автокопии.** Перед восстановлением из файла и перед «Очистить все данные» приложение само сохраняет JSON-копию в
  `Documents/AutoBackups` (видна в «Файлы → На iPhone → Кошелёк», хранятся последние 5). Если восстановление не удалось, прежние данные возвращаются.
- **Ошибки сохранения** показываются алертом (`ModelContext.saveOrReport`), а не теряются.
- **Схема данных.** Хранилище версионировано (`AppSchemaV1`, `AppMigrationPlan`). Если меняете модель, не правьте V1: добавьте V2 и этап
  миграции. Безопасно только добавлять свойства с значением по умолчанию или опциональные. Если хранилище всё же не открылось,
  показывается экран восстановления, который откладывает старые файлы в сторону (ничего не удаляется).
- **UI-тесты удаления** (`KoshelekUITests`): удаляют операцию, взнос, цель, бюджет, регулярный платёж, счёт и категорию через интерфейс.
  Запускайте в оптимизированной сборке, именно там проявлялся сбой:

```bash
xcodebuild -project Koshelek.xcodeproj -scheme Koshelek -destination 'platform=iOS Simulator,name=<имя симулятора>' \
  -only-testing:KoshelekUITests SWIFT_OPTIMIZATION_LEVEL=-O test
```

## Приложение для Apple Watch

Часы показывают сводку и позволяют быстро ввести расход или доход. Хранилище остаётся одно, на iPhone, а часы связаны
с ним через WatchConnectivity (прямая связь телефон ↔ часы, без интернета и бэкенда).

- **Экраны:** сводка (баланс, доходы и расходы за месяц, прогноз, счета, кнопка «Добавить»), бюджеты с прогрессом, последние операции.
- **Ввод:** сумма на экранной клавиатуре, затем категория (недавние сверху) и счёт, если их несколько. Если телефон доступен,
  операция уходит сообщением и сразу подтверждается; кроме того, она всегда ставится в фоновую очередь `transferUserInfo`.
  Часы хранят неподтверждённые операции («Ждёт отправки») и досылают их, когда связь появляется; телефон игнорирует дубли по id.
  Подтверждением считается ответ телефона или появление операции в его снимке.
- **Как устроено:** `Koshelek/Domain/WatchSync.swift` описывает общие модели (`WatchSnapshot`, `WatchEntry`) и входит в оба таргета.
  На телефоне `WatchSnapshotBuilder` собирает снимок, `WatchSyncService` отправляет его после каждого сохранения (с задержкой),
  а `WatchEntryHandler` принимает операции с часов (повторная доставка не создаёт дубль).
  На часах `WatchSession` хранит последний снимок и очередь отправки. Суммы форматируются на телефоне, поэтому на часах те же числа.
- **Таргет** `KoshelekWatch` (watchOS 10+) встроен в iPhone-приложение: отдельно ставить не нужно, он появится на часах вместе с приложением.
  Исходники лежат в `KoshelekWatch/`, строки в `KoshelekWatch/Resources/Localizable.xcstrings` (скрипт `gen_strings.py` собирает оба каталога).

Проверка в симуляторе: нужны рантаймы iOS и watchOS одной major-версии (например, iOS 27.1 + watchOS 27). Создайте пару
`xcrun simctl pair <часы> <телефон>`, поставьте iPhone-приложение, затем соберите схему `KoshelekWatch` и поставьте
`Debug-watchsimulator/KoshelekWatch.app` на часы (встроенная копия в симуляторе сама не регистрируется как парная).
DEBUG-аргументы часов: `-sampleSnapshot` (пример данных без телефона) и `-autoEntry` (отправить тестовый расход через 4 секунды).
Журнал связи на часах пишется в `Documents/debug.log` контейнера приложения, на телефоне в os_log (категория `watch-sync`).

```bash
# сборка только часов
xcodebuild -project Koshelek.xcodeproj -scheme KoshelekWatch -destination 'generic/platform=watchOS Simulator' build
```

## Дизайн

Тёплая бумажная палитра (`#F5F4EE` / `#262624`), единственный акцент терракота `#D97757`, системный serif для заголовков
и крупных цифр, SF Pro для текста. Все цвета, шрифты, отступы и радиусы собраны в `DesignSystem/Theme.swift`.
